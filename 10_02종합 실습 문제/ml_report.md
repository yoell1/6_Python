# 공공 자전거 장기 연체 예측 — 결과 보고서

- 노트북 : `ml_solution.ipynb`
- 데이터 : `data/clean_rentals.csv` (이전 파이프라인 실습 최종 결과, 13,501행) + `data/users.csv` (10,000행)
- 예측 대상 : `is_overdue_100m` — 대여 시간 100분 초과면 1 (원래 기준 24시간은 해당 건이 0건이라 강사님 공지로 100분으로 변경)

### 요약

- 담당자가 말한 "정확도 84%" 의 정체는 **모델이 전부 정상이라고 답한 결과**다. 연체가 약 18%뿐인 불균형 데이터라 아무것도 배우지 않아도 정확도가 82% 이상 나온다.
- `class_weight="balanced"` 로 연체를 잡기 시작하게 만들 수 있지만, **AUC 가 약 0.49 로 동전 던지기 수준**이다. 피처를 하나씩 검사해도 모두 AUC 0.50 ± 0.01 이라, 현재 데이터에는 연체를 예측할 정보가 없다.
- 비용 기준 최적 임계값(0.35)에서 39.6% 를 절감하지만, 이는 **모델 없이 전원에게 독촉하는 것과 사실상 같은 결과**다. 절감은 모델이 아니라 비용 비대칭(FN 15,000원 ≫ FP 2,000원)에서 나온다.

### STEP 2 · 결합과 가입 기간

- `users.csv` 를 `user_id` 기준 `how="left"`, `validate="many_to_one"` 으로 결합 → 결합 전후 **13,501행 → 13,501행** (중복 없음)
- 가입 기간 `member_days = (rent_time - join_date).dt.days`

#### 발견 : 가입 기간 음수 6,160건 (45.63%)

| 항목 | 범위 |
|:--|:--|
| 대여일 | 2022-01-01 ~ 2022-12-31 |

가입일이 대여일보다 늦은 행이 절반 가까이 된다. 데이터 오류로 판단하고 강사님께 확인한 결과 "여러 방법을 비교해 보라" 는 답을 받았다.

- 기본 처리 : 음수 → 0 (`clip(lower=0)`), 원래 음수였던 행은 `join_error = 1` 로 표시, 원본은 `member_days_raw` 로 보관

### STEP 6 · 모델 비교 ★

| 모델 | 정확도 | 정밀도 | 재현율 | F1 | AUC |
|:--|--:|--:|--:|--:|--:|
| Dummy (most_frequent) | 0.8193 | 0.0000 | 0.0000 | 0.0000 | 0.5000 |
| LogisticRegression | 0.8193 | 0.0000 | 0.0000 | 0.0000 | 0.4828 |
| LogisticRegression (balanced) | 0.4907 | 0.1741 | 0.4857 | 0.2564 | 0.4824 |
| RandomForest | 0.8193 | 0.0000 | 0.0000 | 0.0000 | 0.4957 |
| RandomForest (balanced) | 0.5622 | 0.1733 | 0.3770 | 0.2374 | 0.4865 |

#### 1. Dummy 와 RandomForest 의 정확도가 같은 이유

RandomForest(와 LR)는 학습했지만 연체를 구분할 패턴을 찾지 못해 **Dummy 처럼 전부 정상(0)으로 예측**했다. 그래서 정확도는 테스트의 정상 비율(81.93%)과 같고, 재현율·정밀도는 0 이다.

#### 2. "정확도 84% 인데 연체를 못 잡는다" 의 원인

Dummy / LR / RF 의 상황이다. 연체가 약 18% 인 불균형 데이터에서는 **전부 정상이라고만 해도 정확도가 82 ~ 84%** 나온다. 하지만 재현율이 0 이므로 실제로 잡아야 할 연체는 한 건도 잡지 못한다. 불균형 데이터는 정확도가 아니라 **재현율, F1, AUC** 로 평가해야 한다.

#### 3. `class_weight="balanced"` 를 쓰는 이유

적은 클래스(연체)를 틀렸을 때 벌점을 더 크게 줘서, 모델이 "전부 정상" 으로 도망가지 못하게 한다. RF 기준 정확도는 0.82 → 0.56 으로 떨어지지만 **재현율이 0 → 0.38** 로 올라 실제로 연체를 잡기 시작한다. 목표는 정확도가 아니라 연체를 잡는 것이므로 이 옵션을 쓴다.

### STEP 7 · 혼동행렬 (RandomForest balanced) ★

| | 예측 : 연체 | 예측 : 정상 |
|:--|--:|--:|
| **실제 연체** | TP 184 | FN 304 |
| **실제 정상** | FP 878 | TN 1,334 |

| 칸 | 자전거 관점 해석 |
|:--|:--|
| TP 184 | 100분 넘게 반납 안 할 이용자를 **미리 잡아 독촉** |
| FN 304 | 연체할 이용자를 **놓쳐서** 방치됨 → 회수 인건비, 연체료 미수납 |
| FP 878 | 제때 반납할 이용자에게 **괜히 독촉** → 문자 비용, 고객 불만 |
| TN 1,334 | 정상 이용자를 그대로 둠 |

#### FN 과 FP 중 더 치명적인 것 : FN

| 오류 | 1건 비용 |
|:--|--:|
| FN (연체를 놓침) | 15,000원 |
| FP (정상을 의심) | 2,000원 |

FN 이 FP 의 **7.5배** 다. 정상 이용자 7명에게 독촉 문자를 보내는 것과 연체 1건을 놓치는 것이 비슷한 손해다. FP 비용 2,000원에는 고객 불만(CS 리소스)까지 이미 포함돼 있다. 다만 FP 가 지나치게 많아지면 이용자 이탈로 이어질 수 있으므로, FN 만 줄이는 것이 아니라 **둘의 총비용을 최소화**하는 지점을 찾는다(STEP 8).

---

### STEP 8 · 비용 기반 임계값 선택 ★

총비용 = FN × 15,000 + FP × 2,000, 임계값 0.05 ~ 0.95 (0.05 간격)

| 임계값 | TP | FN | FP | 재현율 | 정밀도 | 총비용 |
|--:|--:|--:|--:|--:|--:|--:|
| 0.05 ~ 0.30 | 488 | 0 | 2,212 | 1.000 | 0.181 | 4,424,000 |
| **0.35** | **488** | **0** | **2,211** | **1.000** | **0.181** | **4,422,000** |
| 0.40 | 484 | 4 | 2,195 | 0.992 | 0.181 | 4,450,000 |
| 0.45 | 440 | 48 | 2,015 | 0.902 | 0.179 | 4,750,000 |
| 0.50 | 184 | 304 | 878 | 0.377 | 0.173 | 6,316,000 |
| 0.55 | 21 | 467 | 94 | 0.043 | 0.183 | 7,193,000 |
| 0.60 ~ 0.95 | 0 | 488 | 0 | 0.000 | 0.000 | 7,320,000 |

#### 결과

| 방법 | 총비용 |
|:--|--:|
| 아무 예측 안 함 (전부 정상 → 연체 488건 전부 FN) | 7,320,000원 |
| **최적 임계값 0.35** | **4,422,000원** |
| 절감액 | **2,898,000원 (39.6%)** |

F1 최대가 아니라 총비용 최소를 기준으로 고른 이유는 FN 과 FP 의 비용이 7.5배 차이 나기 때문이다. 기본 임계값 0.5 를 그대로 쓰면 총비용 6,316,000원으로 최적보다 약 189만 원 더 든다.

#### 주의 : 이 절감은 모델 덕분이 아니다

임계값 0.35 에서 모델은 2,700건 중 **2,699건을 연체로 예측**했다. 모델 없이 **전원에게 독촉**하면 FN 0, FP 2,212 → 총비용 4,424,000원으로, 최적과의 차이는 **2,000원(1명)** 뿐이다. 모델의 AUC 가 0.49 로 연체와 정상을 구분하지 못하기 때문에, 비용 구조상 "전원 독촉" 이 최선이 된 것이다.

| 순위 | 피처 | 중요도 |
|:--:|:--|--:|

#### 운영팀 보고 (3줄)

1. 모델이 가장 많이 참고한 정보는 **가입 기간 > 대여 시간대 > 요일** 순이므로, 대여 시점에 이 세 가지를 우선 기록·모니터링할 필요가 있다.
2. 단, 현재 모델의 AUC 가 약 0.49 로 연체를 구분하지 못해, 이 정보만으로 연체 고객을 골라낼 수는 없다.
3. 연체를 놓치는 비용(15,000원)이 독촉 비용(2,000원)보다 커서 당분간은 전원 독촉이 유리하며, 과거 연체 이력 등 새로운 정보를 추가로 수집해야 한다.

### 추가 실험 1 · 가입 기간 음수 처리 4가지 비교

같은 모델(RandomForest balanced), 같은 지표로 비교

| 방법 | 학습 행 | 테스트 행 | 정확도 | 재현율 | F1 | AUC |
|:--|--:|--:|--:|--:|--:|--:|
| ① 삭제 | 5,468 | 1,873 | 0.6161 | 0.3254 | 0.2327 | 0.5005 |
| ② 0으로 대체 | 10,801 | 2,700 | 0.5622 | 0.3770 | 0.2374 | 0.4865 |
| ③ -1로 표시 | 10,801 | 2,700 | 0.5619 | 0.3791 | 0.2382 | 0.4916 |

- 네 방법의 AUC 차이는 최대 0.016 으로 **의미 있는 차이가 없고**, 모두 0.5 근처다.
- ① 삭제는 데이터를 약 45% 잃고 테스트 데이터까지 달라져 공정한 비교가 아니다.
- 결론 : 행을 잃지 않는 단순한 방법(② 0 대체 또는 ③ -1 표시)을 쓰면 충분하다. 성능이 낮은 원인은 음수 처리가 아니다.

### 추가 실험 3 · 패턴을 넣은 더미 데이터로 다시 실행

"데이터에 정보가 있으면 같은 코드로 모델이 찾아내는가?" 를 확인하기 위해, 연체 패턴을 일부러 넣은 더미 데이터를 만들어 같은 노트북으로 다시 실행했다.

- 생성 : `make_dummy.ipynb` → `data/dummy_rentals.csv` (원래 데이터와 컬럼 동일, 반납 시각·요금·거리만 다시 생성, 시드 42)
- 실행 : `ml_solution_dummy.ipynb` (`ml_solution.ipynb` 복사본, 데이터 경로만 변경)

#### 넣은 규칙 (행마다 연체 확률)

| 규칙 | 확률 변화 | 해당 비율 |
|:--|:--:|:--:|
| 기본 | 10% | 전체 |
| 20시 이후 대여 | +25% | 약 18% |
| 주말(토, 일) | +10% | 약 29% |
| 가입 1 ~ 30일 신규 | +20% | 약 3% |
| 프리미엄 멤버십 | -7% | 약 29% |

- 확률대로 연체 여부를 뽑고, 연체는 101 ~ 180분, 정상은 10 ~ 100분으로 대여 시간 생성
- 요금 = 대여 시간 × 분당 요금(일반 20원, 전동 30원), 거리 = 속도(일반 8 ~ 15, 전동 15 ~ 25 km/h) × 시간

#### 원래 데이터 vs 더미 데이터

#### 해석

1. **AUC 0.49 → 0.72** : 코드와 모델은 그대로인데 데이터에 패턴이 생기자 모델이 구분해 냈다. 원래 데이터에서 성능이 낮았던 원인이 **데이터**에 있었다는 것이 확인된다.
2. **모델의 가치가 비용으로 드러남** : 원래 데이터에서는 최적 임계값이 사실상 "전원 독촉" 이었지만, 더미 데이터에서는 전원 독촉보다 **95만 원**을 더 줄인다. 이 차이가 모델이 만든 가치다.
3. **중요도가 넣은 규칙과 일치** : 가장 강하고 넓게 넣은 밤 대여(+25%, 18%)가 `hour` 1위, 주말(+10%, 29%)이 `weekday` 2위, 프리미엄(-7%)이 `membership_type` 3, 4위로 나왔다. 단독 AUC 도 `hour` 0.635, `weekday` 0.588, 그룹별 연체율도 BASIC 17.9% vs PREMIUM 10.5% 로 규칙이 그대로 드러난다.
4. **드물게 일어나는 강한 요인은 중요도가 작게 보인다** : 신규 이용자 규칙은 +20% 로 주말의 두 배지만 해당 행이 약 3% 뿐이라 `member_days` 중요도는 0.067(5위) 에 그쳤다. 중요도가 낮다고 그 요인이 약한 것은 아니다.

### 결론

1. **정확도 84% 의 정체** : 불균형 데이터에서 "전부 정상" 이라고만 답한 결과. 재현율 0 이므로 실제 가치는 없다.
2. **현재 데이터로는 연체를 예측할 수 없다** : 모델을 바꿔도(LR, RF), 가중치를 줘도, 전처리를 바꿔도 AUC 가 0.5 근처이며, 피처 단독 검사에서도 예측 정보가 없다.
3. **비용 관점의 판단** : FN 이 FP 보다 7.5배 비싸므로, 예측 모델이 없는 지금은 전원 독촉(또는 임계값 0.35)이 총비용을 39.6% 줄이는 현실적인 선택이다.
4. **다음 단계** : 모델 튜닝보다 연체와 관련된 **새로운 데이터**(이용자의 실제 반납 지연 이력, 대여 목적, 날씨, 반납 대여소까지의 거리 등)를 수집하는 것이 먼저다.
5. **근거 (추가 실험 3)** : 연체 패턴을 넣은 더미 데이터에서는 같은 코드로 AUC 0.72 가 나오고, 전원 독촉보다 95만 원을 더 줄였다. 즉 파이프라인과 모델은 정상이며, 연체와 관련된 정보가 담긴 데이터가 생기면 바로 효과를 낼 수 있다.
