## 1. `@property` 는 왜 붙였나요?

```python
@property
def grade(self):
    return "일반"

print(customer.grade)      # 괄호 없이
```

**"메소드를 변수처럼 쓰려고요."**

`grade()` 대신 `grade` 로 읽게 됩니다. 값을 저장해두지 않고 매번 계산해서 주는 거라,
자식 클래스(VIPCustomer)가 다른 값("VIP")을 돌려줘도 호출하는 쪽은 바꿀 게 없어요.

## 2. `ask("이름 : ", crm.validate_name)` — 함수를 왜 인자로 넘기나요?

```python
def ask(prompt, check):
    while True:
        value = read(prompt)
        try:
            check(value)          # 넘겨받은 함수를 여기서 실행
            return value
        except ... as e:
            print(f"[다시 입력] {e}")
```

**"검사 방법만 다르고 나머지는 똑같아서요."**

물어보고 → 검사하고 → 틀리면 다시 묻는 흐름은 이름·연락처·매니저 전부 같아요.
다른 건 "무엇으로 검사하느냐"뿐이라 그 부분만 바깥에서 넣어줍니다.

`sorted(key=lambda ...)` 와 같은 원리예요. `sorted` 도 "무엇으로 비교할지"만 받잖아요.

## 3. `raise CancelInput()` — 예외를 왜 취소에 쓰나요?

```python
def read(prompt):
    text = input(prompt).strip()
    if text.lower() == "q":
        raise CancelInput()
    return text
```

**"몇 단계 깊이 있든 한 번에 빠져나오려고요."**

`q` 를 치는 시점은 `menu_register` 안의 `ask` 안의 `read` 안이에요.
`return` 으로는 세 단계를 하나씩 올라와야 하는데, `raise` 는 `except` 가 있는 곳까지 바로 튑니다.

에러가 아니라 **"흐름 탈출"** 용도로 쓴 거예요.

## 4. `"가" <= ch <= "힣"` — 이게 왜 되나요?

```python
for ch in name:
    if not ("가" <= ch <= "힣"):
        raise InvalidNameError(name)
```

**"문자도 크기 비교가 되니까요."**

모든 글자는 유니코드 번호를 갖고 있고, 한글 완성형은 `가`(44032)부터 `힣`(55203)까지
**연속으로** 배치돼 있어요. 그 사이면 완성형 한글입니다.

`ㅏ`, `ㄱ` 같은 자모는 다른 구역(12593~)에 있어서 자연히 걸러져요.

## 5. `MENU_ACTIONS = {"1": menu_register, ...}` — 딕셔너리에 함수를 넣었네요?

```python
MENU_ACTIONS = {
    "1": menu_register,       # 괄호 없음 = 함수 자체
    "2": menu_list_all,
    ...
}

action = MENU_ACTIONS.get(choice)     # 함수를 꺼냄
action(crm)                           # 꺼낸 함수를 실행
```

**"`if/elif` 7개 대신이에요."**

괄호 없이 `menu_register` 라고 쓰면 실행이 아니라 함수 자체를 가리켜요.
그걸 딕셔너리에 담아두고, 번호로 꺼내서 나중에 실행합니다.

메뉴를 추가하려면 함수 하나 만들고 딕셔너리에 한 줄 넣으면 끝이라, 확장하기 쉬워요.

## 6. `RATE` 를 클래스 변수로 둔 이유는?

```python
class Customer:
    RATE = 0.01
    def add_point(self, amount):
        earned = int(amount * self.RATE)

class VIPCustomer(Customer):
    RATE = 0.05                # 이것만 덮어씀
```

**"메소드를 안 고치고 값만 바꾸려고요."**

`add_point` 는 부모에 한 번만 있어요. `self.RATE` 로 찾으면 VIP 객체에선 자식의 0.05가 먼저 잡힙니다.
오버라이딩 없이 동작이 달라지는 거예요.

## 한 줄 요약

| 질문 | 답 |
|---|---|
| `@property` | 메소드를 변수처럼 |
| 함수를 인자로 | 검사 방법만 바꿔 끼우려고 |
| 예외로 취소 | 몇 단계든 한 번에 탈출 |
| `"가" <= ch` | 유니코드 번호가 연속이라 |
| 딕셔너리에 함수 | `if/elif` 대신 |
| `RATE` 클래스 변수 | 메소드 안 고치고 값만 |
