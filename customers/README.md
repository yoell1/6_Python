# 고객 관리 CLI 프로그램

일반 고객과 VIP 고객을 상속으로 분리하여, 등급별 포인트 적립과 혜택을 차등 적용하는 콘솔 프로그램입니다.

## 실행 방법

```
cd customers
python main.py
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `models.py` | 도메인 클래스 (`Customer`, `VIPCustomer`) 와 사용자 정의 예외 6종 |
| `crm_manager.py` | 고객 목록 관리 (`CRMManager`) — 등록·조회·수정·삭제, 입력값 검증 |
| `input_utils.py` | 사용자 입력 도우미 — 재입력, `q` 취소, 숫자·y/n 검사, 연락처 자동 보정 |
| `main.py` | 메뉴 루프, 메뉴별 함수, 예외 처리 |

참고 구조(3파일)에서 `input_utils.py` 를 추가했습니다. `main.py` 가 입력 처리 세부까지 담아 길어져서, "어떻게 입력받나" 와 "무슨 메뉴를 하나" 를 분리했습니다.

## 기능

| 메뉴 | 기능 |
|---|---|
| 1 | 고객 등록 — ID 자동 채번 (C001, C002, …), 일반/VIP 선택 |
| 2 | 전체 고객 조회 |
| 3 | VIP 고객만 조회 |
| 4 | 특정 포인트 이상 보유 고객 검색 (포인트 높은 순) |
| 5 | 연락처 수정 |
| 6 | 구매 금액 입력 → 등급별 포인트 적립 (일반 1%, VIP 5%) |
| 7 | 고객 삭제 (확인 후) |
| 0 | 종료 |

## 클래스 구조

```
Customer                    일반 고객, RATE = 0.01
  └─ VIPCustomer            VIP 고객, RATE = 0.05, manager 추가
```

- 적립률은 **클래스 변수 `RATE`** 로 두고, 자식 클래스에서 값만 덮어씀
- `add_point()` 는 부모에만 있고 `self.RATE` 를 참조하므로 자식은 자동으로 5% 적용
- `__str__` 은 부모가 기본 형식을 만들고, 자식이 `super().__str__()` 에 담당자를 덧붙임
- 연락처는 화면 출력 시 가운데 4자리를 마스킹 (`010-****-5678`)

## 사용자 정의 예외

| 예외 | 발생 상황 |
|---|---|
| `DuplicateContactError` | 이미 등록된 연락처로 등록·수정 시 |
| `CustomerNotFoundError` | 존재하지 않는 고객 ID 조회·수정·삭제 시 |
| `InvalidContactError` | 연락처 형식이 `010-0000-0000` 이 아닐 때 |
| `InvalidNameError` | 이름·매니저가 한글/영문 외 문자를 포함하거나 20자를 넘을 때 |
| `InvalidAmountError` | 구매 금액이 0 이하일 때 |
| `EmptyInputError` | 필수 입력값이 비어 있을 때 |

검사는 `crm_manager.py` 에서 `raise`, 화면 출력은 `main.py` 의 `try-except` 에서 처리합니다.
자식 예외를 위에, 부모 예외(`ValueError`, `Exception`)를 아래에 배치했습니다.

## 입력 처리

- 입력 칸마다 조건을 안내 (`이름 (한글/영문, 20자 이내) :`)
- 잘못된 값을 넣으면 **해당 항목만 다시 입력** (처음부터 다시 치지 않음)
- 어느 입력 칸에서든 `q` 를 치면 메뉴로 복귀
- 연락처는 `01012345678`, `010 1234 5678` 처럼 하이픈 없이 쳐도 자동 보정
- 전각 숫자(`１２３`) 는 거부 — 한글 자판 상태로 입력한 숫자 방지
- 고객 ID 는 소문자(`c001`)로 쳐도 대문자로 인식
- 금액은 `10,000` 처럼 콤마를 넣어도 허용
- `Ctrl+C`, `Ctrl+Z` 로 종료해도 오류 없이 정상 종료

## 검증 규칙

| 항목 | 규칙 |
|---|---|
| 이름 · 매니저 | 완성형 한글(가~힣) 또는 영문, 사이 공백 허용, 20자 이내 |
| 연락처 | `010-0000-0000` 형식, 반각 숫자만, 중복 불가 |
| 구매 금액 | 1원 이상 정수 |
| 고객 ID | 자동 채번 (`C001`부터), 삭제된 번호는 재사용하지 않음 |

## 테스트

### 수동 테스트 (직접 실행)

프로그램을 실행해 메뉴 7개를 반복 조작하며 확인. 이 과정에서 아래 문제를 발견해 수정함.

- VIP 여부에 `y`/`n` 외 값(`ㅛ` 등)을 넣으면 일반 고객으로 등록됨
- 잘못된 값 입력 시 처음부터 다시 입력해야 함
- 이름에 숫자·특수문자가 허용됨
- 존재하지 않는 ID 입력 시 메뉴로 튕김
- 입력 조건 안내가 없어 형식을 모르고 틀림
- 메뉴 선택 후 현재 작업이 무엇인지 표시되지 않음

### 자동 로직 검증 (35개 항목, 클래스 직접 호출)

| 구분 | 확인 항목 |
|---|---|
| 등록 | 자동 채번 순서, 실패한 등록은 번호를 소모하지 않음, 삭제된 번호 미재사용 |
| 검증 | 빈 값 · 숫자 이름 · 자모(ㅋㅋ) · 21자 이상 · 연락처 형식 · 011 번호 · 전각 숫자 · 연락처 중복 · VIP 매니저 빈값 |
| 포인트 | 일반 1% · VIP 5% · 누적 · 0원/음수 거부 · 소액(0P) 처리 |
| 조회 | VIP 필터 · 포인트 검색 결과 정렬(높은 순) · 검색 기준값 |
| 수정·삭제 | 중복 연락처로 수정 거부 · 없는 ID 수정/삭제 거부 · 삭제 후 조회 불가 · 삭제된 연락처 재사용 가능 |
| 출력 | 연락처 마스킹 · VIP `__str__` 에 담당자 포함 |
| 도우미 | 하이픈/공백 자동 보정 · y/n 검사 |

### 화면 흐름 검증 (메뉴 7개 전부)

각 입력 칸에 잘못된 값 → 재입력 안내 → 올바른 값 → 정상 처리 순서로 확인.
`q` 취소, `Ctrl+C`, `Ctrl+Z` 종료 시 오류 메시지 없이 종료되는지 확인.

### 정적 검사

`py_compile` (문법), `pyflakes` (미사용 import·변수) — 경고 없음.
